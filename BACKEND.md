# Спільні проєкти та збереження

## Рекомендований бекенд: Supabase

Supabase дає цій статичній сторінці авторизацію, PostgreSQL і Row Level Security. Це підходить для облікових записів, приватних/публічних проєктів, авторських вимірювань і штрихів, а також накладання публічного плану поверх свого.

## Підготовлена схема

1. Створи Supabase project.
2. Відкрий **SQL Editor**, повністю скопіюй уміст файлу [`supabase/schema.sql`](./supabase/schema.sql) у редактор і натисни **Run**. Не вводь у SQL редактор сам текст `supabase/schema.sql` — це назва локального файлу, а не SQL-команда.
3. У **Authentication → Providers** увімкни email-вхід (посилання або код).
4. Додай Project URL і publishable/anon key у frontend-конфігурацію. Не використовуй і не передавай `service_role` key у браузер.
5. Додай URL локальної розробки та продакшну в Auth redirect URLs.

RLS правила у схемі забезпечують:

- користувач редагує і видаляє лише власні проєкти;
- публічні проєкти можна переглядати після входу;
- виміри, штрихи та приховування міток належать автору й доступні для перегляду в публічному проєкті;
- накладання може створювати лише власник цільового проєкту; джерело мусить бути публічним або його власним;
- приватні проєкти інших користувачів не потрапляють у каталог.

## Інтеграція у фронтенді

Фронтенд підключає Supabase Auth і таблиці з `schema.sql`. Для локального запуску поклади у `.env`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
```

`npm run dev` генерує локальний `supabase-config.js` і запускає сторінку на `http://localhost:4173/`. Файл конфігурації ігнорується Git. Для Vercel додай ці самі змінні в **Project → Settings → Environment Variables**; команда збірки `npm run build`, директорія результату `.`.

Після входу власні проєкти, виміри, штрихи й додані предмети зберігаються у Supabase. Позначка «Дозволити іншим переглядати» робить проєкт доступним у каталозі. Перемикач «накласти проєкт» зберігається окремо для кожної пари проєктів. Відмітки, предмети та контури чужого проєкту відображаються read-only. Доступ визначається RLS політиками з `schema.sql`; у браузері використовується тільки publishable key.
